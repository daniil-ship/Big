# Компилятор bigc — архитектура

`src/bigc.asm` — **единственный** исходный файл компилятора: 100% NASM
(x86-64, режим `-f bin`). Никакого C, Python, линкера или внешних библиотек:
файл сам содержит DOS/PE-заголовки и импорты, поэтому

```
nasm -f bin src/bigc.asm -o bigc.exe
```

даёт самодостаточный `bigc.exe` для Windows 11 x64. Цель — **только PE64**;
никакого ELF/Linux в компиляторе нет.

## Конвейер

```
GetCommandLineA → разбор аргументов → чтение .bg (CreateFileA/ReadFile)
  → LEX (токены) → PARSE (AST) → SEMA (типы, слоты, свёртка констант)
  → CODEGEN (эмит машинных команд цели) → BUILD_PE (сборка .exe)
  → запись результата (CreateFileA/WriteFile)
```

## Память

Все арены выделяются `VirtualAlloc` (MEM_COMMIT|MEM_RESERVE, PAGE_READWRITE)
и растут линейно, без освобождения:

| Арена        | Размер | Назначение                          |
|--------------|--------|-------------------------------------|
| куча         | 8 МБ   | строки, копии аргументов командной строки |
| токены       | 2 МБ   | массив токенов по 24 байта          |
| узлы AST     | 16 МБ  | узлы по 72 байта                    |
| код          | 8 МБ   | буфер машинных команд цели          |
| rdata цели   | 1 МБ   | строковые литералы + импорты цели   |
| выход        | 16 МБ  | собираемый PE                       |

## Узел AST (72 байта)

```
+0  kind      +8 N_A   +16 N_B   +24 N_C   +32 N_D
+40 N_E       +48 N_F  +56 N_G   +64 next
```

Основные узлы: `FUNC` (имя, параметры, `nparams|rettype<<32`, тело, id),
`BLOCK`, `LET` (имя, инициализация, тип, слот), `ASSIGN`, `IF`, `WHILE`,
`FOR`, `RETURN`, `EXPRSTMT`, `EINT`, `ESTR`, `EBOOL`, `EIDENT`, `EBIN`,
`EUN`, `ECALL` (имя, `argc`, список аргументов, `func_id`).

## Лексер и парсер

- Лексер: один проход, `//` и `/* */` комментарии, строки с экранированием,
  числа, идентификаторы (ключевые слова распознаются по таблице).
- Парсер: рекурсивный спуск; выражения — алгоритм приоритетного разбора
  (Pratt): `||` → `&&` → `==/!=` → сравнения → `+ -` → `* / %` → унарные.
  **Важная инварианта:** `ecx` несёт минимальный приоритет через все
  рекурсивные вызовы — функции `parse_unary`/`parse_primary` обязаны его
  сохранять (`push/pop rcx`).

## Семантический анализ

- Для каждой функции строится таблица переменных (записи по 32 байта:
  указатель имени, длина, слот, тип). Параметры занимают слоты с 0,
  локальные — дальше.
- Проверяются: существование переменных/функций, арность вызовов,
  типы в `let` (строковый литерал ↔ `str`), наличие `main`.
- Целочисленные выражения из литералов сворачиваются в один `EINT`.
- Диагностика: `diag_named` печатает `error: <сообщение> <имя>` в stderr.
  **Инварианта:** `WriteFile` портит все «летучие» регистры
  (`rcx rdx r8 r9 r10 r11` и `rax`) — между записями значения передаются
  только через стек/каллируемо-сохраняемые регистры.

## Генерация кода

- Байты команд цели пишутся напрямую (`EMIT`/`emit_seq`) в кодовую арену,
  метки и переходы разрешаются фикс-листами после генерации.
- Соглашение сгенерированного кода: кадр `rbp`, локальные переменные в
  `[rbp - 8*slot]`; аргументы вызываются через стек слева направо,
  при нечётном числе аргументов выравнивающий пуш кладётся **под** аргументы,
  чтобы `arg_0` оказался в `[rbp+16]` вызванной функции.
- Строковые литералы копируются в `.rdata` цели (`cg_add_string`,
  обязательно с проверкой нулевой длины); строковая переменная — пара
  слотов (адрес, длина).
- **Инварианты эмиттера:** `EMIT` портит `rcx` и `rsi` (а `emit_seq` ещё и
  `al`) — после `EMIT` нельзя читать поля узла через `rsi`, метки
  (`cg_*_label`) оборачивают `EMIT` в `push/pop rcx`, значения кэшируются
  в `r9/r12-r15` до эмитта.
- Встроенный рантайм цели (функции `print_str`, `print_int`, `newline`)
  генерируется статическими блобами: `GetStdHandle(-11)` + `WriteFile`.
  `print_int` переводит число в десятичные цифры в стеке (поддержка минуса).

## Сборка PE (build_pe)

Выходной файл цели:

- заголовки: 0x200 байт, секции `.rdata` (RVA 0x1000) и `.text`;
- импорт `kernel32.dll`: `GetStdHandle`, `WriteFile`, `ExitProcess`,
  `SetConsoleOutputCP`, `SetConsoleCP` — через дескриптор/ILT в `.rdata`;
- ImageBase `0x140000000`, подсистема 3 (консоль), стек/куча по 64 КБ
  (зарезервировано 1 МБ);
- точка входа: выравнивание стека, установка кодовой страницы 65001,
  `call main`, `ExitProcess(eax)`.

## CLI

```
bigc.exe <file.bg> [-o output.exe]
bigc.exe --help | --version
```

По умолчанию выходной файл — имя входа с заменой расширения на `.exe`
(`hello.bg → hello.exe`). Коды выхода: 0 — успех, 1 — ошибки компиляции
или отсутствие/недоступность входного файла.
